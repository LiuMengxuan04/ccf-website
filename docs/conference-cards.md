# Per-conference deadline cards

`conference-updates.js` now loads before main.js and adds native `<details>` to
conference cards only. There is no standalone top HPDC panel. Search/filter
rendering is unchanged; each newly rendered conference receives its own details.
Summary controls and links stop propagation to the old card-wide navigation.
Keyboard activation uses native summary semantics. All text uses textContent.

Inputs: legacy `hpdc-2027.json` plus optional `conference-deadlines.json`:
`{schema_version:1, conferences:[...]}`. Each entry uses acronym, year, dates,
timezone, sources, submission and verified_at. Community entries additionally
use source_kind:'community', fetched_at and optionally catalogue_ids and rounds.
Each round contains label/dates/comment. Community dates are explicitly labelled
as not individually verified against official sources. Multi-round deadlines are
all displayed, never collapsed into a fabricated single deadline. Catalogue ID
matching precedes acronym fallback. HPDC legacy snapshot stays independent and
replaces an equal-edition aggregate record when its verification is newer.

Links are taken only from supplied records and validated as credential-free
HTTPS URLs, not generated by guessed hostname. Missing/failed files and absent
records leave all conference controls visible with “暂无核实数据” and direct the
reader to the existing catalogue link. They do not assert that dates have not
been announced. Journals receive no deadline controls.

Verification: `node tests/test-conference-cards.cjs`, `node --check js/main.js`,
`node --check js/conference-updates.js`, `git diff --check`. Tests cover data
normalization, safe URLs, legacy HPDC fallback, multi-round community data,
unknown entries, click isolation, repeat render, journal guard and script order.
DOM tests use a lightweight mock; browser visual QA is not claimed. Existing
search/filter code has no changes apart from the card attachment call.
